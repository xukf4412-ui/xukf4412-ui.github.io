## 项目背景

从空间前期构思与表达需求出发，探索能否通过对话，让模糊的空间想法更快变成可浏览、可调整的三维草模。项目面向空间概念探索，也考虑游戏虚拟场景等方向；当前以三个预设空间验证交互，不承诺任意场景生成能力。

## 项目目标与成果

运用 Codex 将想法推进为可公开体验的网站，验证“Agent 引导设计、沙盒呈现空间”的交互方式。当前完成引导式对话、庭院/空间站/展览三类模板、三维浏览与基础编辑、方案比较、本机保存和只读快照分享。

## 简历项目经历

- 从空间前期构思与表达需求出发，借助 Codex 通过逐题澄清形成 SPEC，明确产品目标、交互方式和概念版边界。
- 设计以 Agent 对话为入口、沙盒为视觉载体的空间构思流程，协同 Codex 实现三类预设场景、三维浏览、基础编辑、方案比较及只读分享。
- 将原型组织为输入、执行、场景状态和三维表现四个层次，以规则和模板验证交互流程，为后续模型工具调用预留接口。
- 结合实际访问反馈推进调试和发布，将网站部署至 GitHub Pages；核心场景逻辑通过 7 项自动化测试，形成可公开体验的作品。

## Agent 框架

当前：对话/选项输入 → 规则解析与模板 → SpaceScene 结构化状态与参数校验 → Three.js 空间渲染 → 使用者反馈与下一次调整。

辅助编辑与对话修改作用于同一场景状态；版本记录保留探索路径，草稿保存于本机浏览器，分享链接包含当前方案的只读快照。

后续规划：真实模型理解 → 结构化工具调用 → 复用参数校验与场景操作 → 结果反馈。已预留可选的 read_space / modify_space 浏览器工具接口，尚未完成真实模型调用链路验证。

## 我的贡献与 AI 协作

我负责问题提出、产品定义、交互方向、范围取舍与体验反馈；Codex 协助完成需求文档、代码实现、调试、验证和发布操作。关键判断包括：先通过苏格拉底式逐题问答澄清需求；明确 Agent、沙盒和网站的关系；在没有模型 API 时先完成规则驱动的可交互原型；基于实际访问拦截反馈改用 GitHub Pages 公开发布。

## 能力与边界

这项实践展示需求结构化、AI 协作表达、Agent 系统思维和公开交付能力。当前采用预设规则驱动，尚未接入真实大模型，也未开展系统性的用户研究或效率对比测试。不将概念原型描述为已成熟商用的 AI 产品，不声称实现专业 CAD/BIM 输出、建筑合规验证或游戏引擎资产交付。
